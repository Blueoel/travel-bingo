# Travel Bingo 개발 환경

## 필수 도구

- Node.js 24.14.x
- pnpm 11.9.x
- Git
- Docker Desktop 및 Docker Compose

Codex 데스크톱 환경에는 Node.js와 pnpm이 번들되어 있다. 일반 터미널에서 개발할 때는 `.node-version` 또는 `.nvmrc`와 같은 버전의 Node.js를 설치한다.

## 최초 설정

```powershell
pnpm install --frozen-lockfile
Copy-Item .env.example .env
pnpm env:check
pnpm infra:up
```

`infra:up`은 다음 로컬 서비스를 시작한다.

| 서비스               | 주소                     | 용도                    |
| -------------------- | ------------------------ | ----------------------- |
| PostgreSQL + PostGIS | `localhost:55432`        | 기준 데이터와 공간 쿼리 |
| Redis                | `localhost:56379`        | 캐시와 작업 큐          |
| MinIO API            | `http://localhost:59000` | 로컬 Object Storage     |
| MinIO Console        | `http://localhost:59001` | 저장 객체 확인          |

기본 포트 대신 55xxx/59xxx를 사용해 PC에 이미 설치된 PostgreSQL이나 다른 개발 서비스와의 충돌을 피한다.

## 환경변수

`.env.example`을 `.env`로 복사한다. `.env`는 Git에서 제외된다.

로컬 MinIO를 사용할 때 다음 값을 설정한다.

```dotenv
OBJECT_STORAGE_ACCESS_KEY=travel_bingo
OBJECT_STORAGE_SECRET_KEY=travel_bingo_local_only
```

한국관광공사, 지도, OAuth 키는 해당 연동을 구현할 때 추가한다. 실제 키를 `.env.example`, 소스 코드, 문서에 기록하지 않는다.

## 일반 작업

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm format:check
```

인프라 로그와 종료:

```powershell
pnpm infra:logs
pnpm infra:down
```

## Docker를 사용할 수 없는 경우

현재 PC에 실행 중인 PostgreSQL을 사용할 수 있지만 기존 데이터베이스를 직접 재사용하지 않는 것을 권장한다. 별도의 `travel_bingo` 사용자와 데이터베이스를 만들고 PostGIS 확장을 활성화한 뒤 `DATABASE_URL`을 변경한다.

Redis와 S3 호환 스토리지는 관련 API/Worker 구현 전까지 없어도 순수 도메인 개발과 테스트를 진행할 수 있다. 해당 기능을 구현하기 전에는 Docker Desktop 또는 동등한 격리 환경을 준비한다.

## 포트 충돌 확인

```powershell
netstat -ano | Select-String ':55432|:56379|:59000|:59001'
```

포트를 바꾸면 `compose.dev.yml`과 `.env`를 함께 수정한다.
