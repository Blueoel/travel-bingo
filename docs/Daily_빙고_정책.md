# Daily 산책 빙고 정책

## 1. 확정 규칙

- 매일 하나의 공통 미션 세트를 공개한다.
- 같은 날 모든 사용자는 동일한 25개 미션을 받는다.
- 사용자는 미션 배치만 다르게 받을 수 있다.
- 한 사용자의 당일 배치는 재접속해도 바뀌지 않는다.
- 날짜가 바뀌면 새 Daily 세션을 시작한다.
- 미션은 서로 다른 날짜 사이에서 반복될 수 있다.
- 같은 날짜의 한 판 안에서는 동일 미션을 중복 배치하지 않는다.

## 2. 공정한 개인화 배치

완전 무작위 섞기는 쉬운 미션이 한 줄에 몰려 사용자별 3빙고 난이도를 바꿀 수 있다. 초기 버전은 기준판에 다음 8개 대칭 변환만 적용한다.

1. 원본
2. 90도 회전
3. 180도 회전
4. 270도 회전
5. 좌우 반전
6. 좌우 반전 후 90도 회전
7. 좌우 반전 후 180도 회전
8. 좌우 반전 후 270도 회전

이 변환은 5개 가로, 5개 세로, 2개 대각선의 구성 관계를 모두 보존한다. 따라서 화면 배치는 달라도 각 라인에 포함된 미션 조합은 동일해 3빙고 난이도가 같게 유지된다.

## 3. 배치 결정

```text
variant = hash(dailyDate + userId + dailyVersion) mod 8
```

- 서버가 variant를 계산한다.
- `BingoSession.layoutVariant`에 결과를 기록한다.
- 생성된 25개 `SessionCell.position`도 저장한다.
- 동일 입력은 언제나 같은 결과를 만든다.
- 클라이언트는 variant를 선택하거나 다시 뽑을 수 없다.

## 4. Daily 세션 유일성

DB의 `(userId, templateId, dailyDate)` 유니크 제약으로 사용자가 같은 Daily 판을 여러 번 생성하지 못하게 한다. API의 `Idempotency-Key`도 함께 사용해 네트워크 재시도로 인한 중복 생성을 막는다.

## 5. 날짜 기준

- 초기 운영 날짜 경계는 `Asia/Seoul`의 자정으로 정의한다.
- DB에는 Daily 날짜를 PostgreSQL `date`로 저장한다.
- 템플릿 버전은 공개 후 수정하지 않는다.
- 긴급 변경은 기존 버전을 수정하지 않고 새 버전으로 교체한다.
- 이미 시작한 사용자는 기존 snapshot을 계속 사용한다.

## 6. 경쟁 이벤트와의 구분

| 모드        | 미션 | 배치               | 랭킹 기준         |
| ----------- | ---- | ------------------ | ----------------- |
| Daily 산책  | 동일 | 8개 대칭 중 개인별 | 완료 수·점수 중심 |
| 경쟁 이벤트 | 동일 | 전원 동일          | 완료 수·라인·시간 |

Daily에서도 대칭 변환으로 라인 난이도는 동일하지만, 일상 참여를 우선해 완료 수와 점수를 주요 지표로 사용한다.

## 7. 중복 미션 정책

- 전날과 같은 미션이 다시 등장하는 것은 허용한다.
- 최근 7일 동안의 반복 횟수에 상한을 둘 수 있다.
- 같은 미션이 연속으로 등장하면 점수나 문구를 변형할 수 있다.
- 안전·날씨·계절 미션은 운영자가 Daily 후보군에서 제외할 수 있다.
- 당일 한 판의 25칸에는 동일 `missionId`가 한 번만 들어간다.
