# Travel Bingo UI 디자인 기준

> 기준 이미지: 사용자 제공 3×3 모바일 화면 레퍼런스  
> 적용 대상: 참가자 PWA 전체 화면  
> 원칙: 레퍼런스의 구조와 분위기를 따르되 상표·이미지·캐릭터를 그대로 복제하지 않는다.

## 1. 디자인 방향

Travel Bingo 참가자 앱은 **깔끔한 모바일 유틸리티 UI와 따뜻한 픽셀 여행 게임**을 결합한다.

- 흰색과 옅은 회색을 기본 배경으로 사용한다.
- 제목, 핵심 버튼, 숫자는 검정에 가까운 색으로 명확하게 표시한다.
- 탐험·진행 상태에는 파랑, 초록, 노랑, 주황을 제한적으로 사용한다.
- 캐릭터, 배지, 지역 아이콘은 픽셀아트 스타일로 통일한다.
- 장식보다 진행률, 현재 할 일, 다음 행동을 먼저 보여준다.
- 주요 화면은 한 손 조작과 현장 시인성을 우선한다.

## 2. 디자인 토큰

### 색상

| 토큰              | 권장값    | 용도                      |
| ----------------- | --------- | ------------------------- |
| `surface-canvas`  | `#F7F7F5` | 앱 바깥과 보조 배경       |
| `surface-primary` | `#FFFFFF` | 화면·카드                 |
| `surface-subtle`  | `#F2F2EF` | 탭·비활성 영역            |
| `text-primary`    | `#151515` | 제목·본문                 |
| `text-secondary`  | `#666663` | 설명·보조 정보            |
| `border-default`  | `#E4E3DE` | 카드·구분선               |
| `action-primary`  | `#171715` | 주요 CTA                  |
| `accent-blue`     | `#3868B9` | 활성 내비게이션·일반 진행 |
| `accent-green`    | `#4D9B4A` | 완료·성공·높은 진행률     |
| `accent-lime`     | `#91CB3E` | 히어로 진행 표시          |
| `accent-yellow`   | `#F3BE42` | 진행 중·보너스            |
| `accent-orange`   | `#E9904F` | 방문·주의 상태            |
| `danger`          | `#C94B42` | 오류·반려                 |

색상만으로 상태를 구분하지 않고 아이콘, 텍스트, 패턴을 함께 사용한다.

### 크기와 형태

| 항목             | 기준                            |
| ---------------- | ------------------------------- |
| 모바일 콘텐츠 폭 | 최대 430px                      |
| 화면 좌우 여백   | 16px                            |
| 카드 내부 여백   | 12~16px                         |
| 카드 간격        | 12px                            |
| 카드 모서리      | 12px                            |
| 버튼 높이        | 46~50px                         |
| 작은 탭 높이     | 32~36px                         |
| 터치 영역        | 최소 44×44px                    |
| 카드 테두리      | 1px                             |
| 그림자           | 낮은 명도·짧은 거리로 최소 사용 |

### 타이포그래피

- 한글 본문은 가독성이 높은 고딕 계열을 사용한다.
- 로고, 일부 배지 숫자, 픽셀 그래픽 안의 문구에만 픽셀 폰트를 제한적으로 사용한다.
- 화면 제목은 18~~20px, 카드 제목은 15~~17px, 본문은 14px, 보조 문구는 12px를 기본으로 한다.
- 점수·완료율·남은 시간은 tabular number를 사용해 숫자 폭을 고정한다.

## 3. 공통 레이아웃

### 상단 앱 바

- 높이 약 56px
- 중앙 정렬 화면 제목
- 좌측에는 뒤로가기, 우측에는 검색·공유·설정·더보기 중 하나만 우선 노출
- 홈 화면은 중앙 워드마크와 우측 알림을 사용

### 하단 내비게이션

다섯 개 항목을 고정한다.

1. 홈
2. 탐험
3. 빙고
4. 랭킹
5. 마이

- 아이콘과 짧은 한글 레이블을 함께 사용한다.
- 활성 항목은 `accent-blue`, 나머지는 짙은 회색으로 표시한다.
- 카메라나 위치 권한 시스템 UI가 열려도 복귀 시 선택 상태를 유지한다.

### 카드

- 흰색 바탕, 얇은 회색 테두리, 12px 모서리
- 제목·상태·진행률의 정보 위계를 일정하게 유지
- 전체 카드 클릭이 가능한 경우 화살표를 우측에 배치
- 진행률 막대는 높이 5~7px, 둥근 끝을 사용

### 버튼

- 주요 행동: 검정 배경 + 흰 글자
- 보조 행동: 흰 배경 + 검정 테두리
- 위험 행동: 확인 단계가 있는 붉은 계열
- 한 화면에서 채워진 주요 버튼은 원칙적으로 하나만 사용

## 4. 화면별 적용 기준

### 홈

- 상단에 사용자 인사와 픽셀 캐릭터
- 진행 중 빙고를 작은 썸네일, 이름, `완료 칸 / 25`, 진행 막대로 표현
- 진행 중 이벤트는 큰 일러스트 카드와 남은 시간, CTA로 강조
- 하단에는 오늘의 포인트·거리·업적을 3열 요약 카드로 제공

### 탐험 지도

- 상단에 범위 필터를 segmented control로 제공
- 대한민국 지도는 지역 상태를 네 단계 색으로 표시
- 지도 장식은 바다·배·구름 등 절제된 픽셀 요소 사용
- 하단에 최근 탐험 지역을 가로 카드 목록으로 제공
- 지역 색 외에 범례와 텍스트 상태를 반드시 제공

### 지역 상세

- 상단 히어로 이미지에 지역명, 완료율, 완료 칸 수를 오버레이
- `빙고 목록 / 대표 사진 / 지역 정보` 탭
- 각 테마는 픽셀 아이콘, 이름, 완료 수, 진행 막대로 구성
- 완료·진행·미방문 상태의 색을 일관되게 유지

### 빙고판

- 상단에 `완료 칸 / 25`, 진행 막대, 완료율
- 정사각형 5×5 그리드
- 칸은 제목을 2~3줄 안에서 표시
- 완료 칸은 색·아이콘·테두리로 표현
- 보너스 칸은 별 아이콘과 `FREE` 표시
- 완성된 라인은 칸 상태를 해치지 않는 반투명 연결 표현 사용
- 하단 주요 CTA는 공유 또는 다음 미션으로 화면 상태에 맞게 변경

### 미션 상세

- 제목과 한 줄 설명을 가장 먼저 표시
- 장소/미션 대표 이미지는 16:9에 가까운 큰 카드
- 위치, 인증 방법, 인증 반경, 점수, 예상 시간, 주의사항을 아이콘+텍스트 행으로 정리
- GPS 미션은 `길찾기`와 `미션 시작하기`
- 사진 미션은 `사진 촬영하기`와 `앨범에서 선택`
- 권한 거부나 정확도 부족 시 해결 방법을 같은 화면에서 안내

### 미션 완료

- 픽셀 메달·배지 애니메이션을 중심에 배치
- 완료한 미션명과 획득 점수를 크게 표시
- 현재 진행률과 `완료 칸 / 25`
- 주요 CTA는 `다음 미션 보기`, 보조 CTA는 `빙고판으로 돌아가기`
- 모션 감소 설정 사용자는 정적 화면으로 표시

### 랭킹

- 기간과 범위 필터를 2단 segmented control로 제공
- 상위 3명은 메달 픽셀 아이콘
- 사용자 행은 하단 또는 현재 순위에 고정 강조
- 점수뿐 아니라 집계 기간과 마지막 갱신 시각 표시

### 마이

- 픽셀 아바타, 닉네임, 레벨과 경험치
- 누적 포인트·방문 지역·완료 빙고 3열 요약
- 여행 기록, 배지, 내가 만든 빙고, 설정 메뉴
- 개인정보·사진·위치 삭제 경로를 설정 안에 명확히 배치

## 5. 반응형 기준

- 참가자 앱은 320~430px를 우선 설계한다.
- 431px 이상에서는 모바일 콘텐츠를 중앙 정렬하고 최대 폭을 유지한다.
- 태블릿에서는 지도·지역 카드처럼 공간 활용 가치가 있는 화면만 2열을 허용한다.
- 데스크톱에서도 참가자 앱을 과도하게 넓히지 않는다.

## 6. 관리자 화면 확장

관리자 화면은 참가자 앱과 색상·폰트·모서리·상태 표현을 공유한다.

- 좌측 사이드바 + 상단 상태 바 구조
- 표·필터·검색·지도 중심
- 카드 모서리와 그림자는 참가자 앱보다 절제
- 위험 명령은 검정 CTA 대신 위험색과 2차 확인 사용
- 픽셀아트는 빈 상태·지역 아이콘·배지 미리보기에만 사용

## 7. 구현 원칙

- 화면마다 임의 색상과 간격을 만들지 않고 토큰을 사용한다.
- 픽셀 이미지는 저해상도 원본을 정수 배율로 확대하고 보간을 끈다.
- 관광 사진은 실제 데이터 출처의 이미지와 라이선스를 사용한다.
- 레퍼런스 속 `walkbingo` 명칭, 캐릭터, 사진을 그대로 복제하지 않는다.
- 로딩 skeleton, 빈 상태, 오류, 오프라인, 권한 거부 화면도 정상 화면과 같은 품질로 설계한다.
- 구현 화면은 모바일 viewport 캡처로 레퍼런스와 정보 위계·간격·상태 표현을 비교 검수한다.
